# Test Case - 검색

> 이 문서는 `docs/tc/revised6/search.md`(44건)의 `Test Scenario` 컬럼을 `3 Depth`(테스트 시나리오/목적) 컬럼으로 바꾼 새 문서(revised7)다. 3 Depth는 기존 시나리오 문장을 `{검증 대상} {목적 분류}` 형태의 짧은 목적 문구로 다시 쓴 것이며, 이외 컬럼 값(ID, 1·2 Depth, Preconditions, Steps, Expected, Priority, Requirement ID, Result)과 행 순서는 revised6와 동일하다. 대표 TC 참조(괄호)는 3 Depth에 유지했다. 기존 문서·Spreadsheet는 변경하지 않았다.
> 이 문서는 `docs/tc/revised5/search.md`(44건)를 새 TC 컬럼 구조(`ID | 1 Depth | 2 Depth | Test Scenario | Preconditions | Test Steps | Expected Result | Priority | Requirement ID | Result`)로 변환한 새 문서(revised6)다. `Feature` 컬럼을 `1 Depth`(시스템/도메인)와 `2 Depth`(세부 기능/컴포넌트)로 나누고 `Requirement ID`를 Priority 뒤로 옮겼으며, ID·Scenario·Preconditions·Steps·Expected·Priority·Requirement ID·Result 값과 행 순서는 revised5와 동일하다. 기존 문서·Spreadsheet는 변경하지 않았다.
> 이 문서는 `docs/tc/revised4/search.md`를 tc-writing Skill 번호 표기 규칙(1.5)으로 재작성한 새 문서이며, 기존 문서(`docs/tc/search.md`, `docs/tc/revised/`~`docs/tc/revised4/search.md`)와 Spreadsheet는 변경하지 않았다. 이번 변경은 표기 형식만이다(Test Steps·Preconditions·Expected Result가 2개 이상 항목이면 `1.`, `2.` 번호와 `<br>` 구분, 복수 조건이 한 줄로 이어진 Preconditions는 독립 조건 단위로 분리). TC의 ID·Requirement ID·Scenario·Priority·내용의 의미·행 구성(44건)은 revised4와 동일하다.

> 공통 전제: PC Chrome, Production(https://store.laftel.net/). "로그인"은 테스트 계정 로그인 상태, "비로그인"은 로그아웃(시크릿 창) 상태를 의미한다. 계정 정보는 문서에 기록하지 않는다. "검색페이지 진입"은 `/search`가 표시된 상태를 뜻하고, "검색 결과 화면"은 `/search?keyword=...`가 표시된 상태를 뜻한다. "사전에 확인해 둠"은 PRD에 구체 데이터가 정의되어 있지 않아 테스트 수행자가 Production에서 조건에 맞는 키워드/상품을 미리 찾아 둔다는 의미다. 자동완성 목록은 PRD 표기 "자동완성/추천 검색어"와 같다. 판매종료는 PRD REQ-SEARCH-013의 "상품종료"와 같은 상태로 보고 "판매종료"로 통일한다. 이 Feature의 TC는 브라우저에 저장되는 최근 검색어 외에 Production 데이터를 변경하지 않는다. 각 TC의 Test Steps는 동작 1개(1~2단계)이며, 이전 진입·상태는 Preconditions에 쓴다. Test Steps·Expected Result는 명사형 간략 표기이며, Test Steps·Preconditions·Expected Result 모두 항목이 2개 이상일 때만 `1.`, `2.` 번호를 붙이고 항목 사이는 `<br>`로 구분한다(단일 항목은 번호 없음).

> Risk 참조: Risk 스프레드시트의 `리스크 매트릭스`(RI-Search-001~007, Likelihood/Impact/Risk Score 확정값)를 읽기 전용으로 참조했다(revised~revised4 문서와 동일한 값).

> 상한 대상 추출 결과(PRD 전체 검토): 최대치가 명시된 항목은 REQ-SEARCH-005의 "작품 목록 최대 20개"와 "연관 검색어 최대 10개" 2건이다. 그 외는 상한이 아니므로 대상에서 제외했다. 검색어 글자 수는 하한(최소 1자, REQ-SEARCH-018)만 명시되어 있고 최대 글자 수는 PRD 4.2에서 미확정 추정이다. 최근 검색어 개수도 "100개까지 확인"이며 상한 여부는 미확정 추정이다. 결함 의심 항목의 "최대 20개/10개"는 REQ-SEARCH-005와 같은 상한이 관찰된 기록이다.

- 최대 글자 수 및 최근 검색어 저장 개수 상한은 PRD 4.2에서 미확정 추정이므로 상한 경계값 TC를 작성하지 않았다. 확정되면 추가 필요.
- TC-SEARCH-027, 041 Requirement ID는 PRD에 해당 Requirement가 없어 빈 값(revised4와 동일, 확인 필요).
- TC-SEARCH-010 Priority(P0)는 RI-Search-004 매핑에 따른 값이며 조정 여부 확인 필요(revised4와 동일).
- TC-SEARCH-027, 041 Priority(P2)는 TC 단위 보정값이며 사용자 검토 필요(revised4와 동일).
