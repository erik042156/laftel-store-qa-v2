# Test Case - 카트 (번호 표기 규칙 적용본)

> 이 문서는 `docs/tc/revised6/cart.md`(38건)의 `Test Scenario` 컬럼을 `3 Depth`(테스트 시나리오/목적) 컬럼으로 바꾼 새 문서(revised7)다. 3 Depth는 기존 시나리오 문장을 `{검증 대상} {목적 분류}` 형태의 짧은 목적 문구로 다시 쓴 것이며, 이외 컬럼 값(ID, 1·2 Depth, Preconditions, Steps, Expected, Priority, Requirement ID, Result)과 행 순서는 revised6와 동일하다. 대표 TC 참조(괄호)는 3 Depth에 유지했다. 기존 문서·Spreadsheet는 변경하지 않았다.
> 이 문서는 `docs/tc/revised5/cart.md`(38건)를 새 TC 컬럼 구조(`ID | 1 Depth | 2 Depth | Test Scenario | Preconditions | Test Steps | Expected Result | Priority | Requirement ID | Result`)로 변환한 새 문서(revised6)다. `Feature` 컬럼을 `1 Depth`(시스템/도메인)와 `2 Depth`(세부 기능/컴포넌트)로 나누고 `Requirement ID`를 Priority 뒤로 옮겼으며, ID·Scenario·Preconditions·Steps·Expected·Priority·Requirement ID·Result 값과 행 순서는 revised5와 동일하다. 기존 문서·Spreadsheet는 변경하지 않았다.
> 이 문서는 `docs/tc/revised4/cart.md`(38건)를 개정된 tc-writing Skill 1.5 표기 규칙(복수 항목은 `1.`, `2.` 번호 + `<br>` 구분)으로 재작성한 새 문서이며, 기존 문서(`docs/tc/cart.md`, `revised/`~`revised4/`)와 Spreadsheet는 변경하지 않았다. 표기 형식(번호 표기, Preconditions 조건 항목 분리)만 변경했으며 TC의 ID·Requirement ID·Test Scenario·Priority·내용의 의미·행 구성(38건)·ID 오름차순 정렬은 revised4와 동일하다.
> 공통 전제: PC Chrome, Production(https://store.laftel.net/). 모든 TC는 별도 명시가 없으면 **로그인 상태**(테스트 계정)에서 수행하며, 계정 정보는 문서에 기록하지 않는다. 각 TC의 Preconditions에는 이 로그인 전제를 반복하지 않는다. "선택"은 상품 카드의 체크박스가 체크된 상태, "상품 카드"는 장바구니의 상품 1종(옵션 포함) 단위를 의미한다. 각 TC의 Test Steps는 사용자 동작 1개(1~2단계)만 쓰며, 이전 진입·상태는 Preconditions에 쓴다. 표기: Test Steps·Preconditions·Expected Result는 항목이 2개 이상일 때만 `1.`, `2.` 번호를 항목마다 붙이고 항목 사이는 `<br>`로 구분하며, 단일 항목은 번호를 붙이지 않는다. Preconditions는 독립된 조건 단위로 나누어 번호를 붙인다.
> **Production 데이터 변경 주의**: 장바구니 담기, 수량 변경, 삭제는 테스트 계정의 장바구니 데이터를 생성/수정/삭제한다. 해당 TC는 Preconditions에 "[Production 데이터 변경]"으로 표기했으며, 수행 전 사용자 승인이 필요하다(CLAUDE.md 11절).
> Risk 참조: Risk 스프레드시트의 `리스크 매트릭스`(RI-CART-001~008 확정 점수)와 `리스크 아이템`(RI-CART-NNN별 REQ 매핑)은 revised 문서에서 읽기 전용으로 참조한 내용을 그대로 사용했다(이번 작업에서 시트 재조회 없음).
> 제외 범위: 품절/판매종료 상품이 장바구니에 있을 때의 표시·선택·삭제 결과, "품절 삭제" 실제 삭제 결과, 재고 상한의 고정 수치는 PRD 4.2 미확인 항목이므로 TC로 만들지 않았다.
> Feature 간 연계: 장바구니 아이콘 진입 중 상품상세 경유 경로는 TC-PRODUCT-DETAIL-008이 대표로 검증하고 본 문서 TC-CART-002는 메인페이지 아이콘 클릭, TC-CART-026은 URL 직접 입력을 검증한다. 구매하기 이후 주문/결제 화면의 구매하기 버튼(N, 금액)은 TC-ORDER-021이 대표이며 본 문서는 장바구니 화면 내 표시만 검증한다.

## Priority 산정 근거

Risk 스프레드시트 `리스크 매트릭스`의 RI-CART-001~008 Likelihood/Impact/Risk Score는 사용자가 확정한 값이므로 Priority 산정의 우선 근거로 사용한다(Skill 3절). 매핑된 RI의 Risk Score를 Priority 매핑표(P0 16~25 / P1 9~15 / P2 1~8)에 적용했으며, 동일 RI의 TC는 동일 Priority를 유지한다. RI와 REQ 매핑은 revised 문서(`리스크 아이템` 시트의 REQ ID 열 기준)를 따랐다. 분리·신규로 부여된 TC는 원 TC와 같은 RI/Priority를 따르며 TC 단위 보정은 없다.

## 미결 질문 (revised3 유지 + 상한 항목 추가, 임의 결정 없음)

- 1. 재고 상한 고정 수치가 PRD에 없어 "상한 정확히 N 도달" / "상한 미만(N-1)" TC를 만들지 않았다. 재고 수치를 알 수 있는 테스트 상품(잔여재고 N개 확인 가능)과 상한 도달 시 수량 표시 기대 결과를 확인해야 한다. 기존 TC-CART-008(수량 증가)이 상한 미만 증가의 일반 동작은 검증한다.
- "품절 삭제" 팝업에서 "취소"/"삭제" 클릭 후 결과, 품절/판매종료 상품 표시·선택·삭제 결과는 PRD 4.2 미확인이라 TC 미작성.
- 선택 0건일 때 배송비 문구 표시, 일부만 선택된 그룹에서 그룹 체크박스 클릭 시 결과는 PRD에 명시가 없어 TC 미작성.
