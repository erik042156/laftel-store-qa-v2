# Test Case - 찜

> 이 문서는 `docs/tc/revised6/wishlist.md`(57건)의 `Test Scenario` 컬럼을 `3 Depth`(테스트 시나리오/목적) 컬럼으로 바꾼 새 문서(revised7)다. 3 Depth는 기존 시나리오 문장을 `{검증 대상} {목적 분류}` 형태의 짧은 목적 문구로 다시 쓴 것이며, 이외 컬럼 값(ID, 1·2 Depth, Preconditions, Steps, Expected, Priority, Requirement ID, Result)과 행 순서는 revised6와 동일하다. 대표 TC 참조(괄호)는 3 Depth에 유지했다. 기존 문서·Spreadsheet는 변경하지 않았다.
> 이 문서는 `docs/tc/revised5/wishlist.md`(57건)를 새 TC 컬럼 구조(`ID | 1 Depth | 2 Depth | Test Scenario | Preconditions | Test Steps | Expected Result | Priority | Requirement ID | Result`)로 변환한 새 문서(revised6)다. `Feature` 컬럼을 `1 Depth`(시스템/도메인)와 `2 Depth`(세부 기능/컴포넌트)로 나누고 `Requirement ID`를 Priority 뒤로 옮겼으며, ID·Scenario·Preconditions·Steps·Expected·Priority·Requirement ID·Result 값과 행 순서는 revised5와 동일하다. 기존 문서·Spreadsheet는 변경하지 않았다.
> 본 문서는 `docs/tc/revised4/wishlist.md`를 tc-writing Skill 1.5 번호 표기 규칙으로 **재작성한 새 문서**이다. 표기 형식(번호 `1.` 통일, 복수 항목 번호 부여, Preconditions 조건 항목 분리)만 변경했으며 TC 구성(57건)·ID·Requirement ID·Priority·내용의 의미는 revised4와 동일하다. 기존 문서(`docs/tc/wishlist.md`, `revised/`~`revised4/`)와 Spreadsheet는 변경하지 않았으며 Spreadsheet에도 반영하지 않았다.

> 공통 전제: PC Chrome, Production(https://store.laftel.net/). "로그인 상태"는 테스트 계정 로그인 상태, "비로그인 상태"는 로그아웃(시크릿 창) 상태를 의미하며 모든 TC에서 이 두 표현으로 통일한다. 계정 정보는 문서에 기록하지 않는다.
> 용어 통일: PRD의 "찜 아이콘"/"하트 아이콘"/"하트"는 상품 카드 기준 **"찜 아이콘"**(찜 상태 = 보라색 채움, 찜 안 한 상태 = 빈 하트)으로, 작품 페이지 전용 하트 버튼과 "작품" 탭 섹션 우측 하트는 **"작품 찜 아이콘"**으로 통일한다.
> **Production 데이터 변경 주의**: 찜 추가/해제/편집 삭제 TC는 테스트 계정의 Production 찜 데이터를 생성·수정·삭제한다. 해당 TC는 Preconditions 맨 앞에 "[Production 데이터 변경]"으로 표기했으며, 실행 전 사용자 승인이 필요하다(CLAUDE.md 11절). 각 TC는 종료 시 찜 상태를 원복하는 것을 전제로 한다.
> Feature 간 연계: 상품상세 진입점(하단 고정 영역, "같은 작품 굿즈" 카드)의 찜 동작은 상품상세 Feature의 TC-PRODUCT-DETAIL-016, 026, 027, 028, 030과 겹침 후보가 있으며, 이번 재작성에서도 임의로 정리하지 않고 양쪽에서 동작 기준으로 각각 유지했다(겹침 후보는 보고서 미결 질문 참조).
> 표기 규칙(Skill 1.5): Steps·Preconditions·Expected는 명사형 간략 표기, 항목이 2개 이상일 때만 `1.`, `2.` 번호를 항목마다 붙이고 항목 간 구분은 `<br>`이다. 단일 항목은 번호 없이 쓴다.
> Risk 참조: Risk 스프레드시트 `리스크 매트릭스`(RI-WISHLIST-001~007, 확정 점수)를 revised3 문서와 동일하게 읽기 전용으로 참조했다. Priority는 revised3와 동일하다.
> ID 규칙: revised3의 ID를 그대로 유지했으며 신규 추가 TC는 없다. 원본·revised~revised3에서 쓰인 최대 번호는 TC-WISHLIST-059이므로 향후 추가 시 060 이상을 부여한다(003, 005 결번 재사용 금지).

## 미결 질문 (사용자 확인 필요, 임의 결정 금지)

1. 찜 가능 상품 개수 상한 N이 있는지, 있다면 값과 초과 시 기대 결과(차단/토스트 등)는 무엇인지(상한 3개 TC 작성 전제).
2. `/my/wish` "상품" 탭 무한 스크롤의 1회 로드 개수와 최대 로드 개수, 정확히 N개/N-1개 찜 데이터를 Production 테스트 계정에서 확보하는 방법.
3. 상품상세 Feature TC(TC-PRODUCT-DETAIL-016, 026, 027, 028, 030)와 겹침 후보(하단 고정 영역, "같은 작품 굿즈" 카드의 찜 동작)를 대표 TC와 연계 확인으로 정리할지 여부(revised3와 동일하게 임의 정리 안 함).
