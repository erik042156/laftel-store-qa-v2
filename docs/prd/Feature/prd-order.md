# Feature PRD - 주문

## 1. 개요

라프텔 스토어(https://store.laftel.net/)의 주문 기능. 상품상세의 "구매하기 > 바로구매" 또는
장바구니 화면의 "구매하기" 등 여러 경로를 통해 동일한 주문/결제 화면(`/check-out/{uuid}`)으로
진입하며(상품상세의 "구매하기 > 장바구니"는 주문/결제 화면이 아닌 장바구니 담기 동작으로,
카트 Feature PRD REQ-CART-001 범위), 배송지 입력, 주문상품 확인, 쿠폰 적용, 결제수단 선택,
결제금액 확인, 필수 동의 체크
후 "구매하기"를 클릭하면 PG 결제창으로 이동한다. Project PRD상 결제 자체(PG 결제창 진입 이후의
실제 결제 처리, 결제 완료/실패 처리)는 Out of Scope이며, 본 문서는 결제창 진입 이전까지의
주문서 작성 프로세스를 다룬다.

## 2. 관련 Project PRD 참조

- 문서: `/docs/prd/project-prd.md`
- 상태: 승인완료 (승인일: 2026-09-03)
- Project PRD 6번(In Scope)에 명시된 "주문(결제 제외)" 항목에 해당.

## 3. 사용자 조작 시나리오

1. 상품상세 화면에서 "구매하기" → 옵션/수량 선택 후 확장된 영역에 "장바구니"/"바로구매" 두 개의
   선택지가 노출된다. 이 중 "바로구매" 버튼을 클릭하거나, 장바구니 화면의 "구매하기" 버튼을
   클릭하면 동일한 주문/결제 화면(`/check-out/{uuid}`)으로 이동한다. ("장바구니" 버튼을 클릭한
   경우에는 장바구니에 상품이 담기며 주문/결제 화면으로 바로 이동하지 않는다 — 해당 동작은 카트
   Feature PRD REQ-CART-001 참조)
2. 주문/결제 화면 상단에는 뒤로가기와 "주문/결제" 타이틀이 표시되고, 이어서 배송지 입력 섹션,
   주문상품 목록, 쿠폰 섹션, 결제수단 섹션, 결제금액 요약, 주문 내용 확인 및 결제 동의 영역,
   하단 고정 "구매하기" 버튼이 순서대로 노출된다.
3. 배송지 섹션에서 받는 사람/휴대폰번호/주소(우편번호 찾기 경유)를 입력하고, 배송 요청사항을
   드롭다운(사전 정의 문구 3종 또는 직접입력)에서 선택한다. 계정에 이전에 저장된 배송지가
   있으면 진입 시 해당 값이 자동으로 채워진 상태로 표시된다.
4. 주문상품 섹션에서 판매자 그룹 단위로 나열된 상품(이미지, 작품명, 상품명/옵션명, 수량, 금액)을
   확인한다. 수량 변경은 이 화면에서 이루어지지 않는다.
5. 쿠폰 섹션에서 적용 가능한 쿠폰 여부를 확인하고(없을 경우 안내 문구 노출), 결제수단 섹션에서
   결제수단을 확인하며, 결제금액 섹션에서 총 결제금액과 세부 내역(상품 금액/배송비/할인)을
   확인한다.
6. 주문 내용 확인 및 결제 동의 영역의 3개 필수 항목을 모두 체크한다.
7. 배송지 필수값과 필수 동의가 모두 충족된 상태에서 하단 "구매하기" 버튼을 클릭하면 PG 결제창이
   노출된다. 필수값이 누락된 경우 각각 에러 메시지 또는 안내 팝업으로 진행이 차단된다.

## 4. Requirements

### 4.1 확인된 요구사항

**진입**
- **REQ-ORDER-001**: 상품상세 "구매하기 > 바로구매", 장바구니 화면의 "구매하기" 등 여러 경로 모두 동일한 주문/결제 화면(`/check-out/{uuid}`)으로 연결된다. (상품상세 "구매하기 > 장바구니"는 주문/결제 화면 진입 경로가 아니며, 해당 동작은 카트 Feature PRD REQ-CART-001을 따른다.)
- **REQ-ORDER-002**: 주문/결제 화면 상단에 뒤로가기와 "주문/결제" 타이틀이 표시된다.

**배송지 섹션**
- **REQ-ORDER-003**: 배송지 섹션에는 "받는 사람"(필수, 이름), "휴대폰번호"(필수, 숫자만 입력 가능), "주소"(필수, 우편번호+우편번호 찾기 버튼/주소/상세주소), "배송 요청사항"(선택, 드롭다운, 기본값 "문 앞에 놓아주세요.")이 표시된다.
- **REQ-ORDER-004**: "받는 사람"/"휴대폰번호"/"주소"를 비운 채 "구매하기"를 클릭하면 각 필드가 빨간 테두리로 표시되고, 필드별 에러 메시지("이름을 확인해 주세요.", "휴대폰번호를 확인해 주세요.", "우편번호 찾기를 통해 주소를 입력해 주세요.")가 노출된다.
- **REQ-ORDER-005**: "우편번호 찾기" 클릭 시 카카오 우편번호 검색 모달(검색창 + 검색 팁 안내 + "Powered by kakao")이 노출된다.
- **REQ-ORDER-006**: "휴대폰번호" 입력 필드는 숫자 외 문자 입력 자체가 필드 레벨에서 차단된다.
- **REQ-ORDER-007**: "배송 요청사항" 드롭다운은 "문 앞에 놓아주세요."(기본 선택), "부재 시 연락 부탁드려요.", "배송 전에 연락 주세요.", "직접입력" 4개 옵션과 하단 "취소" 버튼으로 구성된 선택 팝업 형태다.
- **REQ-ORDER-008**: "직접입력" 선택 시 드롭다운 표시값이 "직접입력"으로 바뀌고, 그 아래 텍스트 입력창("배송 요청사항을 입력해 주세요." placeholder)과 글자 수 카운터(예: "0/50", 최대 50자)가 나타난다.
- **REQ-ORDER-019**: 계정에 이전에 입력해 저장된 배송지 정보(받는 사람/휴대폰번호/우편번호/주소)가 있으면, 주문/결제 화면 진입 시 해당 값이 비동기로 자동 채워진 상태로 표시된다(최초 이용 등 저장된 배송지가 없는 계정은 빈 값으로 표시).

**주문상품 섹션**
- **REQ-ORDER-009**: "주문상품 N건" 타이틀 아래, 판매자(예: "Laftel Store") 그룹 단위로 상품 카드(이미지, 작품명, 상품명/옵션명, 수량, 금액)가 나열된다.
- **REQ-ORDER-010**: 옵션이 있는 상품은 "옵션: {옵션명} | 수량" 형식으로 옵션명과 수량이 함께 표시된다.
- **REQ-ORDER-011**: 주문/결제 화면 자체에는 수량 변경 UI가 없으며, 이전 단계(장바구니 등)에서 확정된 수량이 표시만 된다.

**쿠폰**
- **REQ-ORDER-012**: "쿠폰" 섹션에 "쿠폰 할인" 라벨과 ⓘ 안내 아이콘이 있으며, 적용 가능한 쿠폰이 없을 경우 "적용가능한 쿠폰이 없어요" 문구가 표시된다.

**결제수단**
- **REQ-ORDER-013**: "결제수단" 섹션에는 현재 "신용/체크카드" 1개 옵션만 존재하며, 라디오 버튼으로 기본 선택된 상태로 표시된다.

**결제금액**
- **REQ-ORDER-014**: "결제금액" 섹션에는 총 결제금액(강조 표시), 총 상품 금액, 배송비, 상품 할인 항목이 표시된다.

**주문 동의**
- **REQ-ORDER-015**: "주문 내용 확인 및 결제 동의" 영역에 3개 필수 체크 항목(주문 내용 및 결제 내역 확인, 약관 및 유의사항 확인, 개인정보 제공 동의)과 하단 안내 문구(청약철회 조건/기간, 청약철회 제한 사유, 청약철회 신청 경로, 미성년자 결제 동의 안내, 기타 문의 경로)가 표시된다.
- **REQ-ORDER-016**: 필수 동의 항목을 체크하지 않은 상태에서 "구매하기"를 클릭하면 버튼 자체는 비활성화되지 않지만, 클릭 시 "주문내용 확인 및 결제에 동의해 주세요" 알림 팝업(확인 버튼)이 노출되어 진행이 차단된다.

**하단 고정 버튼 및 결제 진입**
- **REQ-ORDER-017**: 화면 하단에 "{총 결제금액}원 구매하기 (N)" 형태의 버튼이 고정 노출되며, N은 총 수량이 아닌 주문에 포함된 상품 종류 수(카드 개수)를 의미한다.
- **REQ-ORDER-018**: 배송지 필수값 입력 및 필수 동의 체크가 모두 완료된 상태에서 "구매하기"를 클릭하면 PG 결제창이 노출된다(그 이후 실제 결제 처리 자체는 Out of Scope).

### 4.2 미확인 / 추가 확인 필요 항목

- 실제 결제 완료 후 주문 완료 화면(주문번호 표시 등)의 구성 — 실제 결제를 진행하지 않아 검증 범위에서 제외
- 내 스토어 > 주문내역(`/orders`) 화면 구성(주문 상태, 목록, 배송 상태 등) — 완료된 주문이 없어 검증 범위에서 제외
- 주문 취소 절차(취소 사유 선택, 확인 팝업 등) — 완료된 주문이 없어 검증 범위에서 제외
- 주문 관련 1:1 문의 진입 및 화면 — 주문내역 진입이 전제되므로 이번 범위에서 제외
- 재고 상황에 따른 수량 추가/변경 가능 조건의 정확한 동작 — 카트/상품상세 PRD 영역과 겹칠 수 있어 참고사항으로만 남김

## 5. Feature 단위 In Scope / Out of Scope

**In Scope**
- 주문/결제 화면(`/check-out/{uuid}`) 진입(여러 경로 공통)
- 배송지 입력 및 필수값 검증(받는 사람/휴대폰번호/주소), 우편번호 찾기, 배송 요청사항 선택/직접입력, 저장된 배송지 자동 채움
- 주문상품 목록 표시(상품/옵션/수량/금액)
- 쿠폰 섹션 노출(적용 가능 쿠폰 없음 케이스)
- 결제수단 섹션 노출
- 결제금액 요약 노출
- 주문 내용 확인 및 결제 동의(필수 체크 항목, 미체크 시 진행 차단)
- 하단 고정 "구매하기" 버튼 및 PG 결제창 진입 여부 확인(결제창 진입까지만)

**Out of Scope**
- PG 결제창 내부의 실제 결제 처리(결제 수단 입력, 결제 완료/실패 처리) — Project PRD상 결제 자체 Out of Scope
- 주문 완료 화면, 주문내역(`/orders`) 조회, 주문 취소, 1:1 문의 — 이번 검증 범위에서 확인되지 않아 4.2에 미확인 항목으로 남김(향후 별도 확인 필요)
- 장바구니 화면 자체의 상품 선택/수량 조절/삭제 UI — 카트 Feature PRD 범위
- 쿠폰 적용 시 UI 및 금액 변화(적용 가능 쿠폰 있는 케이스) — 검증 범위 제외
- 로그인/회원 계정 관리 기능 자체

## 6. 예외 / 에러 케이스

- 배송지 필수값(받는 사람/휴대폰번호/주소) 미입력 상태로 "구매하기" 클릭 시 필드별 에러 메시지 노출, 진행 차단 (REQ-ORDER-004)
- 필수 동의 미체크 상태로 "구매하기" 클릭 시 "주문내용 확인 및 결제에 동의해 주세요" 알림 팝업 노출, 진행 차단 (REQ-ORDER-016)
- 휴대폰번호 필드 숫자 외 문자 입력 차단 (REQ-ORDER-006)
- 적용 가능한 쿠폰이 없는 경우 안내 문구만 노출 (REQ-ORDER-012)

## 7. 비고

- 본 문서는 Project PRD의 "주문(결제 제외)" 정의에 따라 PG 결제창 진입 여부까지만 확인하며, 실제
  결제 완료 이후의 주문 완료/주문내역/주문취소/1:1문의 프로세스는 이번 검증 범위에서 다루지
  않았다(4.2 참조). 이는 Production 결제 데이터 생성을 사용자 승인 없이 임의로 진행하지 않는다는
  원칙에 따른 것이다.
- 상품상세 Feature PRD에서 정의한 상품 상태(판매중/예약구매/판매종료/품절)가 주문 시점에 어떻게
  반영되는지(예: 주문 진행 중 품절/판매종료로 전환된 상품 처리)는 이번 인터뷰에서 다뤄지지 않아
  이 문서에 포함하지 않았다.
- 장바구니(카트) 화면 자체의 상세 기능은 별도 Feature PRD(카트)에서 다룰 예정이며, 본 문서에서는
  주문/결제 화면으로의 진입점 목적 범위 내에서만 언급했다.
